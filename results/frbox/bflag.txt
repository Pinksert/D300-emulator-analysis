C wfmode 语义矩阵：bit1 = OR 等待，bit0 = 满足后清位（与教科书相反）
========================================================================
干净机（boot 到空闲、任务 2 未起），先 set_flg(3,0x300) 再 wai_flg：
  ptn     mode  说明            →  err  steps  satisfied  位模式(后)
  000300  0     AND 成立         →  0    102    True       00000300
  000900  0     AND 不成立        →  0    150    False      00000300
  000300  2     OR  成立         →  0    100    True       00000300
  000900  2     OR  成立(只看一位)   →  0    100    True       00000300
  000800  2     OR  不成立        →  0    147    False      00000300
  000100  1     AND 成立+清位      →  0    104    True       00000000
  000300  3     OR  成立+清位      →  0    102    True       00000000
  000100  0     AND 成立不清       →  0    102    True       00000300

读法：满足 ≈100 步、不满足 ≈147–150 步 —— 多出来的那段是
「登记等待 → 请求一次重调度 → 复查」的兜底路径。r12 恒为 0：
内核只表示「受理」，等没等到要看位模式。mode=1/3 跑完后位模式被清。

E 注入实验：把位放进去，主循环会不会动
========================================================================
  对照（不注入）              覆盖 +0    调用 +376  位模式 00000700→00000700 结束 PC=00041B14
  注入 0x200000          覆盖 +4    调用 +376  位模式 00000700→00000700 结束 PC=00041892
      新地址： 41B72 41B74 41B76 41B78

读法：注入 0x200000 只让 wai_flg 多走 4 个地址（41B72–41B78，满足分支）；
调用方拿完结果就无条件跳回 clr_flg，位立刻被清掉 —— 所以主循环照旧。

F 主循环真正的门：0x9F58D08F 那个字节，从来没被写过
========================================================================
boot 后门字节 = 00
装配 + 主循环 100 万步：门字节写入 0 次，当前值 00，调用 6774 次
42 条 ISR 全扫后：门字节写入 0 次，值 00（新地址 837）
结论：门字节 boot 后是 0，装配、100 万步主循环、42 条 ISR 都没人写它 ——
主循环一直走「字节为 0」那条边，wai_flg 只是空转的让出点。
这就是 V23 说的「等外部事件」：缺的是**写这个字节的那个硬件**，不是中断。

H 计数器速率标定：只要动一个字就够，跟 0x813 没关系
========================================================================
  rate= 1：总步数 591610   调用 2262  覆盖 2632  PC=000406D6 服务分布={-83: 1, -55: 6, -53: 6, -48: 3, -47: 1117, -46: 1117, -27: 1, -23: 11}
  rate=16：总步数 591610   调用 2262  覆盖 2632  PC=000406D6 服务分布={-83: 1, -55: 6, -53: 6, -48: 3, -47: 1117, -46: 1117, -27: 1, -23: 11}

读法：两档速率的总步数**完全相同** —— 等走字循环的容差是从内存读的一个字节
（实测 0/1 量级），计数器动一个 tick 就满足。所以 0x813 不是这条路的延时参数，
这道墙的语义只要求「会走字」。（V23 报告里「延时比例不代表真实时长」这句不再适用。）

========================================================================
能报 / 不能报
========================================================================
能报：
  * B 段服务分发表 13 条（服务号 → 处理函数地址），slp_tsk/ext_tsk 是空桩
  * flag 对象布局：0x680008B8+(N-1)*0x10，+4 等待 TCB、+8 位模式、+0xC 表项背指
  * wfmode 语义：bit1=OR、bit0=满足后清位（与教科书 μITRON 相反）
  * wai_flg 不是「立即返回 E_OK」：内核只表示受理，等没等到看位模式；
    主循环是忙轮询（5 万步 188 圈，clr_flg @0x12016C + wai_flg @0x1203BE）
  * 主循环结构：清 0x200000 → 查门字节 0x9F58D08F → wai_flg → 无条件跳回；
    wai_flg 的返回值没人用，它只是「让出一次 CPU」
  * 门字节 boot 后是 0，装配/百万步/42 条 ISR 都没人写它 —— 缺的是写这个字节的硬件
  * 0x80 的静态置位者在显示绘制路径 0x12E630；0x200000 在 0x12F1A8（任务侧）
  * 42 条 ISR 没有一条能置 0x200000
  * 计数器速率 1 vs 16 总步数完全相同：容差 0/1 量级，一个 tick 就够，0x813 与之无关
不能报：
  * 门字节什么时候会被写（写它的那个硬件没建模）
  * 0x200000 位对应什么逻辑事件（只定位到置位点，没定位到触发条件）
  * 0x813 的实际用途（已排除「等走字循环的延时参数」这一种）
  * 「相机跑起来了」（真实外设事件源仍未建模）

⚠️ 口径：所有 set/clr/wait 都是替固件调内核，不是硬件或别的任务真的产生了事件。
