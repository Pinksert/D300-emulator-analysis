A. 载荷 +8 的真身：清空函数 0x12E602 里的编号循环
========================================================================
静态（0x12E602 全段）：
0x0012E612: 9F859F58D508  ldi:32 op1=0x9, i32=0x9f58d508, op2=0xf, op3=0x8, ri=0x5
0x0012E618: C004  ldi:8 op1=0xc, i8=0x0, ri=0x4
0x0012E61A: C08D  ldi:8 op1=0xc, i8=0x8, ri=0xd
0x0012E61C: 1254  stb op1=0x1, op2=0x2, rj=0x5, ri=0x4
0x0012E61E: A414  add op1=0xa, op2=0x4, u4=0x1, ri=0x4
0x0012E620: C460  ldi:8 op1=0xc, i8=0x46, ri=0x0
0x0012E622: AA04  cmp op1=0xa, op2=0xa, rj=0x0, ri=0x4
0x0012E624: FAFA  blt:d op1=0xf, cc=0xa, rel9=0xfa

  r5 = 槽位基址 0x9F58D508、r4 = 0、r13 = 8；循环体是
  `stb r4,@(r13,r5)`（0x12E61C）→ `add r4,#1` → `cmp r4,#70` → `blt` →
  `add r5,#0x0C`。所以 **+8 = 槽位自己的编号**。

  ⚠️ V35 判「没人写 +8」是因为静态只找『立即数 0x9F58D508 的引用』，
     而这个循环的基址在 r5 里 —— `stb @(r13,r5)` 用的是寄存器偏移。

动态（只跑 0x12E602，600 步返回=True）：槽位 +8 写入 70 笔
  70/70 且值 = 索引：True
  抽样：槽0=0，槽1=1，槽2=2，槽3=3，槽4=4
  写入者 = 0x9F58D510（`stb` 本身；首笔落在 0x00000000）

  末尾还发了一个事件：0x12E630 set_flg(3, 0x80) —— 「队列初始化好了」
  最后 0x12E634 ret。

C. 调用者链：任务 5 入口 → 0x12E006
========================================================================
全片 call 指令 23536 条
  0x12E006 显示初始化           ← 1 处 0x12DFB8
  0x12DFAE 任务 5 入口         ← 0 处 

0x12DFAE 自己不是被 call 进来的 —— 它是任务入口。任务表 0x54C00 记录 4：
  @0x00054C70  68 00 01 ec 00 05 00 04 00 00 00 00 40 00 00 00 00 12 df ae 9f 80 36 a4 00 00 00 00
    +0x00 TCB   = 0x680001EC
    +0x04 编号  = 0x00050004
    +0x0C flags = 0x40000000
    +0x10 **入口** = 0x0012DFAE
    +0x14 栈顶  = 0x9F8036A4

⚠️ 记录 0 = 任务 1，所以记录 4 = **任务 5**。0x12DFAE 是任务 5 的入口，
   不是 V26 记的「任务 4」。任务 4 的入口是 0x00126454。

任务 5 入口的前几条：
0x0012DFAE: 1708  st op1=0x1, op2=0x7, op3=0x0, ri=0x8
0x0012DFB0: 1781  st op1=0x1, op2=0x7, op3=0x8, rs2=0x1
0x0012DFB2: 0F01  enter op1=0x0, op2=0xf, u10=0x1
0x0012DFB4: 9B080062  ldi:20 op1=0x9, i20=0x62, op2=0xb, ri=0x8
0x0012DFB8: D026  call op1=0xd, op5=0x0, rel12=0x26
0x0012DFBA: D09E  call op1=0xd, op5=0x0, rel12=0x9e
0x0012DFBC: C130  ldi:8 op1=0xc, i8=0x13, ri=0x0
0x0012DFBE: D8D1  call:d op1=0xd, op5=0x1, rel12=0xd1
0x0012DFC0: 1680  stb op1=0x1, op2=0x6, rj=0x8, ri=0x0

  → 0x12DFB8 `call 0x12E006`：显示初始化是任务 5 开机第一件事。
  → 所以「0x12E006 没人调用」的真正原因是**任务 5 从来没被启动过**。

D. 任务 5 起不来：sta_tsk 改了 TCB，派发却不选它
========================================================================
boot 后任务 5 的 TCB @0x680001EC：
  68 00 01 ec 68 00 01 ec 00 00 00 10 00 04 00 00 00 00 00 00 ff ff ff ff 00 00 00 00 ff ff ff ff 00 00 00 00 00 05 4c 70 68 00 0a 08
  +0x08 状态 = 0x10（0x10 = 休眠）

sta_tsk(5) → {'steps': 128, 'err': 0}
  之后 TCB：68 00 00 20 68 00 00 20 00 00 00 00 00 04 00 00 00 00 00 00 ff ff ff ff 9f 80 36 a4 ff ff ff ff 00 00 00 00 00 05 4c 70 68 00 0a 08
  +0x08 状态 = 0x00（0 = 就绪）、+0x18 保存 SP = 0x9F8036A4

  但就绪位图 0x45984 = 0x2E80A800（sta_tsk 前后一样）
  → TCB 进了「就绪」，调度器的那张位图却没它 —— 所以派发永远选不到任务 5。
  这一格留给下一版（要接的是「就绪位图 ↔ TCB」的同步点）。

E. 方法学：`ret` 读 DR1，不读栈 —— 旧探针的「跑完」是假返回
========================================================================
fr_emu 里 `ret` 的实现：
    if mn in ('ret', 'ret:d'):  tgt = self._dr(1)   # ← 返回地址寄存器
    dr = [TBR, RP, SSP, USP, MDH, MDL]               # dr[1] 就是 RP

所以「往栈上写返回地址 + 改 SP」根本没人看。函数体内若有 `call`，
DR1 会被子调用的返回地址覆盖，结尾的 `ret` 于是回到「子调用之后」。

  函数                     栈法                           DR1 法
  0x12E006 初始化            30000 步 停在 0x000404E0      746 步 停在 0x000407DC
  0x12E6F8 提交             30000 步 停在 0x000404E0      315 步 停在 0x000407DC
  0x12E1EC 取描述符           30000 步 停在 0x000404E0       20 步 停在 0x000407DC

  栈法全部撞进 0x404E0（`bra -1` 兜底自旋）—— 看上去「跑了很多步」，
  其实一次都没返回。**结论里的内存值仍然有效**（写入发生在自旋之前），
  但「函数跑完了」这件事是假的。V38 起统一用 brealos.call_fn。

F. 阻塞型服务在非任务上下文里：报错或卡死
========================================================================
裸内核调用（kernel_call，从空闲任务上下文发起）：
  set_flg (id= -48) → err = 0    （93 步）
  clr_flg (id= -47) → err = 0    （84 步）
  wai_flg (id= -46) → err = -33  （66 步）
  wai_sem (id= -53) → err = 0    （88 步）
  slp_tsk (id= -41) → err = -17  （58 步）

整段调取首 0x12E63A（它第一件事就是 wai_sem(17)）：
  → {'steps': 3000, 'pc': 5036, 'ret': False}
  wai_sem 在非任务上下文里**不返回错误、也不返回成功**，就是卡住。
  这更正 V36 的「直接进 0x12E63A，wai_sem(17) 立刻执行并返回 0」——
  那句是栈法假返回的产物。

G. 取首的真实寄存器语义：R4 = is_empty，R5 = 载荷
========================================================================
  非空 载荷=90  → 15 步  r4=00  r5=5A  读了 9F58D500、9F58D504、9F58D510
  非空 载荷=37  → 15 步  r4=00  r5=25  读了 9F58D500、9F58D504、9F58D510
  空表 载荷=-   → 12 步  r4=01  r5=00  读了 9F58D500

  0x12E64A is_empty → 0x12E652 空则返回 0 → 0x12E662 `ldub r5,@(8,r0)`
  → 0x12E66E `mov r4,r5`。所以 **R5 才是载荷**，R4 是中间结果；
  搬到 R4 发生在 sig_sem 之后 —— V36 说「返回值在 R4」只在整段跑完时才成立。

H. 边界与口径
========================================================================
可报：
  · 槽位 +8 = 槽位编号（0..69，70/70），由 0x12E602 的循环写入
  · 0x12E006 完整跑通（746 步 / 151 笔写），做了五件事
  · 它唯一的调用者是 0x12DFB8，而 0x12DFAE 是**任务 5** 的入口
  · sta_tsk(5) 把 TCB 状态改成就绪，但就绪位图不变 → 派发不到
  · `ret` 读 DR1（RP）；栈法调用是假返回
  · wai_sem 在非任务上下文里卡死，wai_flg 返回 -33

不可报：
  · 「显示任务跑起来了」——任务 5 仍然没被调度（就绪位图那一格没通）
  · 任何画面（V26 已定论：绘制函数不写像素、无帧缓冲）
  · direct page 那几个寄存器（0x38/0x39/0x3A/0x60/0x62/0x63/0x66/0x67）的语义
  · 0x9F58DA85 是「初始化标志」只是**位置 + 时机**推断，没有读者证据
  · -33 这个错误码的具体名字（只报数值）
