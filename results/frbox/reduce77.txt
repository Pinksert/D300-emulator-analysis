H. 结案、开放项与边界
==============================================================================
H1 KI#298 第一条（部分结案）：两个状态字的**字段写路径**已定位 —— WORD_A 31 条 / 12 偏移、WORD_B 109 条 / 12 偏移；偏移 0 无写点，bit3 恒 0 的原因不是「固件没有写点」。
H2 KI#298 第二条（部分结案）：8 槽填充源 = 0x1758EC 的 24 轮开机清零（24 个可枚举地址）+ 0x175958 的槽 0 写回；更正 V76 「另三个加载点不是生产者」。
H3 KI#298 第三条（部分结案）：vec 0x2D ISR 触碰 0x5C003000 / 0x7000000A / 0x9F58DA86；仍不知对应什么硬件事件。
H4 新硬规矩 65（基址写 / 字段写 / 栈写三分）与 66（borh u4 是高半字节掩码）。
H5 仍开放：偏移 0 由谁在真机上置 bit3、字段写路径的触发任务与时刻、8 槽写回函数被谁调用、302 个提交调用点的真机触发任务、vec 0x2D 的硬件事件、真机让 r4 非 0 的事件语义、0x12E636 返回非 0 条件、真机 tick 源（KI#191）、13 组 ISR 各自硬件事件、[12,13,14,15] 激活机制（KI#257）。
H6 边界：全部 r4 注入 / raise_irq / kernel_call 都是反事实补全；归约是静态数据流，不等于真机执行过。不能报显示链通了 / 出画面 / 系统跑起来了 / 真机如此 /「补一次 set_flg 就唤醒成功」。
H7 设施：frbox/reduce77.py（40 个纯函数）、probe/exp_reduce_v77.py、results/frbox/reduce77.txt；test_v77() 与版本见 frbox_selftest.py / frbox/__init__.py。
