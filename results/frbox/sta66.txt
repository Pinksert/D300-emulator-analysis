B  先证伪：返回码寄存器有判别力、走的是真内核（独立第二台机器）
==============================================================================
B1 这台机器 svc_hook=None、int_hook=method ⇒ `int #0x40` 走真向量表 0x040668，不是 `itron`/`ItronKernel` 半主机打桩（打桩下 r12 恒为 E_OK，无判别力）
B2 注入 `kernel_call`（反事实动作，只验证返回码通路，不参与收敛态结论）：
B2a 预热（boot 后**第一次** kernel_call 一律跑满步数上限，与参数无关）：err=748 steps=80000 ⇒ 不计入样本
     svc=-23   tid=29  → err=-35    steps=69     (空闲任务号，内核拒绝)
     svc=-23   tid=1   → err=0      steps=128    (首次启动任务 1)
     svc=-23   tid=1   → err=-63    steps=90     (重复启动任务 1)

B4 ⚠️ 这是 `kernel_call` 注入工具的边界，不是内核行为：第一次调用从 SAFE_PC(0x0407DC) 起会跑满 80000 步上限、r12 是垃圾值 748。本版显式 预热一次，之后五个样本全部在 128 步内正常返回；越界样本不纳入判定。

E  四层判定：受理 / 已激活 / 上过 CPU / 收敛时还活着吗（本版主结论）
==============================================================================
E1 第 1 层「内核受理」：16 个任务号的 sta_tsk 全部返回 E_OK(0)：[1, 3, 4, 5, 6, 7, 9, 10, 11, 16, 17, 20, 21, 26, 27, 28]
E2 第 2 层「已激活」：TCB 脱离 DORMANT(state≠0x10) 且分配了 saved_sp 的 16 个：[1, 3, 4, 5, 6, 7, 9, 10, 11, 16, 17, 20, 21, 26, 27, 28]
E3 第 3 层「上过 CPU」：任务入口 PC 被覆盖的 16 个：[1, 3, 4, 5, 6, 7, 9, 10, 11, 16, 17, 20, 21, 26, 27, 28]
E4 第 4 层「收敛时状态」：这 16 个里 state=0x04 等待的 16 个；就绪位图 0x00000000、就绪队列占用 0 个 ⇒ **全部挂着等，没有一个在跑**
E5 三层差集：1→2 层 []；2→3 层 [] ⇒ 对这 16 个任务，「受理 / 已激活 / 上过 CPU」是同一个集合，V65 那句保守判断可以收窄
E6 未被任何 sta_tsk 启动、仍休眠(state=0x10)的任务 11 个：[8, 12, 13, 14, 15, 18, 19, 22, 23, 24, 25]
E7 其中 4 个任务号 [12, 13, 14, 15] **全 ROM 没有 sta_tsk 静态点**（27 点只覆盖 23 个任务号）⇒ 它们要么根本不靠 sta_tsk 启动，要么由别的机制激活，本版未解
E8 反过来看：入口跑过但本轮没有 sta_tsk 返回码的是 [2, 29] —— 任务 2 是开机装配任务、29 是空闲任务，都是 BOOT 阶段固件自建的。
E9 判据边界：`err=0` 只说明内核受理；`state≠0x10`+有栈说明已激活；只有入口 PC 覆盖才说明**真上过 CPU**；`state=0x04` 说明它现在在等。四层不能互相替代，也不能拿「不在就绪队列」当「没启动」。

E10 ⚠️ 窗口自证（第四台独立机器，RUN=1000000）：V65 栽过「RUN=20000 窗口假象」，所以「收敛时全挂着」必须先排除 500000 步也只是窗口。
     500000 步：末 PC=0x0407DC、位图 0x00000000、队列 0、入口跑过 18、sta_tsk 命中 16
    1000000 步：末 PC=0x0407DC、位图 0x00000000、队列 0、入口跑过 18、sta_tsk 命中 16
     29 个任务 state 差异任务号：[]；入口 ran 集合差异：[]；PC 覆盖对称差集 0 个
     ⇒ 四项逐项相同，500000 步不是窗口假象，收敛结论成立

G  能说 / 不能说
==============================================================================
能说：
  1. 16 个命中点 = 16 笔调用、16 个任务号，服务返回码全部 E_OK(0)；r12 通路经 −17/−35/−63 三个反例证明有判别力。
  2. 这 16 个任务全部脱离 DORMANT 且入口 PC 全被覆盖 ⇒ **受理 / 已激活 / 上过 CPU 三层重合**，KI#253 那句保守判断可以收窄。
  3. 收敛时 16 个任务 state 全是 0x04 等待、就绪位图 0、队列空 ⇒ 整机停在空闲不是「没启动」，是**全都起来过又全都挂起**。
  4. 11 个休眠任务里 12/13/14/15 全 ROM 没有 sta_tsk 点（E7）；另 11 个静态启动点未命中（C6），两组不是同一批。
  5. 每次 sta_tsk 返回后立刻进 0x040D32 派发，返回点 +2 被执行两次是派发重放。
  6. V65 收敛末 PC 0x0407DC（空闲任务）复现；设备策略与 V65 逐字相同。
不能说：
  · 不能报「16 个任务现在都在运行」—— 它们全部在等待态，只有空闲任务在跑。
  · 不能把「已启动且跑过」推成「显示任务跑通了」：显示链 5 PC 里 0x12E6F8 / 0x12E752 仍未命中，两个状态字仍是 0。
  · 不能报显示链通了 / 出画面 / 找到真机 A↔B 通道。
  · 不能把 B 段的 kernel_call 注入当成收敛态行为；那是独立第二台机器上的反事实。
  · 不能拿 state==0 或「在就绪队列」当「已激活」的判据（收敛时队列已清空，这会让 E2 与 E3 自相矛盾）；也不能把「返回点 ×2」当成「服务被调用两次」。
