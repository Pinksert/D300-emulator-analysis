A 链表四件套（都在 ROM 里，都是 call @r12 间接调用）
==============================================================================
  0x124F46 init   / 0x124F4E is_empty / 0x124F5A insert / 0x124F7A unlink

  A1 init(head=0x9F58D000)：写 2 笔
       pc=00124F46 [9F58D000] = 9F58D000
       pc=00124F4C [9F58D004] = 9F58D000
       head 区 = 9f 58 d0 00 9f 58 d0 00 → 空表

  A2 is_empty(0x124F4E)：
       空表     返回 1   内存有没有被改：False
       1 节点   返回 0   内存有没有被改：False
       3 节点   返回 0   内存有没有被改：False
       → 返回 1 = 空、0 = 非空；不改内存（纯查询）

  A3 insert：往 1 节点链（A）里插 B，逐笔写入（r4 = head、r5 = node）
       pc=00124F5C [9F58D204] = 9F58D000
       pc=00124F60 [9F58D200] = 9F58D100
       pc=00124F62 [9F58D000] = 9F58D200
       pc=00124F68 [9F58D104] = 9F58D200
       walk = ['0x9f58d200', '0x9f58d100']（新节点在链首）

  A4 unlink(r4 = 节点)：从 3 节点链里摘中间那个
       摘之前：['0x9f58d300', '0x9f58d200', '0x9f58d100']
       摘之后：['0x9f58d300', '0x9f58d100']（返回 r4 = 9F58D200）
       反向走：['0x9f58d100', '0x9f58d300']
       ⚠️ 传哨兵进去会破坏链（固件不检查参数）

C 表项 +0 的真语义：第一项是表头
==============================================================================
  两张对象表的首项 +0：
    信号量表   @00054F2C  +0 = 0x00280010 → 高半字 40（实际条数 40） / 低半字 16（项宽 16）
    标志表    @000551B0  +0 = 0x00110010 → 高半字 17（实际条数 17） / 低半字 16（项宽 16）
  → 两个高半字分别等于两张表的**条数**，两个低半字都等于**项宽**

  每个对象的参数放在「自己槽位 + 16」处，两个半字 = [初始计数 | 上限]：
    slot   +0           描述谁     计数  上限
     1   0x00280010   sem  0      40    16
     2   0x00010001   sem  1       1     1
    15   0x00000007   sem 14       0     7
    28   0x000000FF   sem 27       0   255
    30   0x000000FF   sem 29       0   255
    40   0x00010001   sem 39       1     1
    表尾 0x551AC = 0x00010001   sem 40       1     1

  核对：40 项的计数全都等于「下一项 +0 的高半字」——全部命中

==============================================================================
D 那三个 0 计数是「计数信号量」，不是「被占用」
==============================================================================
  id  初始计数  上限   类型
  14       0       7   计数信号量（从 0 起）
  27       0     255   计数信号量（从 0 起）
  29       0     255   计数信号量（从 0 起）
  其余 37 个：初始 1 / 上限 1 → 二值互斥量
  → 7 与 255 是**上限**（max count），不是别的表的编号
  sem 17（显示队列锁）= 1 / 1 → 二值

E 更正 V33：0x124F46 的调用点是 44 处，不是 2 处
==============================================================================
  0x00124F46  立即数  44 处 / rel12 相对调用 0 处
  0x00124F4E  立即数  87 处 / rel12 相对调用 0 处
  0x00124F5A  立即数  88 处 / rel12 相对调用 0 处
  0x00124F7A  立即数  43 处 / rel12 相对调用 2 处

  V33 的探针把 0x124F46 印成「2 处」是算错了（应为 44 处）；0x124F5A 的 88 处是对的。
  规则不变：判调用者扫 32 位立即数。

F 结论
==============================================================================
能报：
  * 链表四件套：init 0x124F46 / is_empty 0x124F4E / insert 0x124F5A / unlink 0x124F7A
  * is_empty 返回 1=空、0=非空，不改内存；unlink 的参数是**节点本身**
  * 消费端不是「摘 head」：0x12E602 是**清空整队**（init + 清 70 槽 + 通知 0x80）
  * 取首在 0x12E63A（只读首节点的 +8，不摘链）；唯一摘链在 0x12E672，摘完又插回
  * 表项 +0 的真语义：**第一项是表头 [条数 | 项宽]**（40|16 与 17|16 两张表互证）
  * 对象参数在「槽位 +16」处：高半字 = 初始计数、低半字 = 上限
  * sem 14 / 27 / 29 = 计数信号量（上限 7 / 255 / 255，初始 0），其余 37 个是二值
  * 0x124F46 的调用点 44 处（V33 的 2 处是算错）
不能报：
  * 队列里的 70 个槽位分别属于什么界面元素
  * 为什么哨兵的 init 只放在「清空」函数里（本场景没执行 → 链不完整）
  * 计数信号量的「上限」在运行期有没有被检查过（内核代码路径没走到）
  * 有没有像素（仍然一条帧数据都没有）
