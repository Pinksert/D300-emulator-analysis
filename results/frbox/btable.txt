A 对象表的真结构：4 字节表头 + 16 字节记录
==============================================================================
对象表 = 4 字节表头 [条数|项宽] + 16 字节记录 ×N
  记录：+0 对象指针 / +4 编号<<16 / +8 0 / +C [初始计数|上限]
  对象：+0 自指 / +4 等待队列哨兵 / +8 计数 / +C **记录地址**（背指）
  sem  @0x00054F2C 40 条（记录 0x00054F30 起）→ 止于 0x000551B0
  flag @0x000551B0 17 条（记录 0x000551B4 起）→ 止于 0x000552C4
⚠️ 上限只在记录 +C 的低半字，对象里没有存

  sem  表头 @0x00054F2C = 0x00280010 → 40 条 | 项宽 16   记录 0x00054F30 起   止于 0x000551B0
  flag 表头 @0x000551B0 = 0x00110010 → 17 条 | 项宽 16   记录 0x000551B4 起   止于 0x000552C4

  前三条记录（sem）：
    第 1 条 @0x00054F30  对象 0x68000638  编号  1  参数 0x00010001 = [初始 1 | 上限 1]
    第 2 条 @0x00054F40  对象 0x68000648  编号  2  参数 0x00010001 = [初始 1 | 上限 1]
    第 3 条 @0x00054F50  对象 0x68000658  编号  3  参数 0x00010001 = [初始 1 | 上限 1]

  计数信号量三条（14 / 27 / 29）与它们的参数格：
    sem 14 记录 0x00055000  参数 0x00000007 = [初始 0 | 上限 7]  对象计数 0
    sem 27 记录 0x000550D0  参数 0x000000FF = [初始 0 | 上限 255]  对象计数 0
    sem 29 记录 0x000550F0  参数 0x000000FF = [初始 0 | 上限 255]  对象计数 0

  体检：表头自洽 True / 对象↔记录背指异常 0 条 / 反向异常 0 条 / 计数≠初始 0 条
  首尾相接：sem 表止于 0x000551B0，flag 表头在 0x000551B0 → True
  → 两张表是**连续排布**的一张链：sem 表最后一条记录的参数格 0x551AC，flag 表头紧接 0x551B0

B 「初始计数从下一项读」之谜：那个地址就是本条记录的 +0xC
==============================================================================
  sem 14 的记录      = 0x00055000
  记录 +0xC（参数格）= 0x0005500C  值 0x00000007
  V33 说的「下一项 +0」= 0x0005500C  值 0x00000007
  两者是同一个地址：True

  所以「初始计数 = 下一项 +0 的高半字」和「初始计数 = 记录 +0xC 的高半字」
  是同一句话 —— 记录从表头后 4 字节开始，才让这两句看起来不同。

  初始化循环读点（动态记账）：0x408FE 读 0x0028（= 40 条）、0x4090A 读 0x0001
  记录 +0xE 也被读 1 次（0x40900）→ 那是项宽 16 —— 表头两个字它都看了。

E 槽位 +8（取首返回的那个字节）：谁写它？
==============================================================================
  静态：整片固件只有 4 条指令拿得到槽位基址 0x9F58D508 ——
    0x0012E252
    0x0012E612
    0x0012E684
    0x0012E704
  其中 0x12E684 是重挂算槽位、0x12E704 是提交算槽位、0x12E612 是清空、0x12E252 是游标分配。
  四段代码都只写 +0（next）/ +4（prev）/ +9（状态），**没有一处写 +8**。

  动态：boot 期间对槽位区的写入记账（按 +0/+4/+8/+9 分类）
    写入 210 笔，按偏移：{0: 70, 4: 70, 8: 70}
    +8 的写者：['40386']
    （记账里的 pc 是那条 st 执行完之后的 PC，所以 0x40384 那条 st 显示成 0x40386）
    +8 写入的值域：{0}
    0x40384 那一段是通用清零循环（st r0,@r1，r0=0，步长 0x0C 扫 70 格）。

  开门场景（steady + 门字节置 1 + 状态字 bit6）跑到提交 0x12E6F8：
    进入提交时 r4 = 11、r5 = 0xffdfffff
    槽位区写入 12 笔，按偏移：{0: 2, 4: 3, 9: 7}
    +8 的写入：0 笔
    链：head 9F58D500：2 个节点（前向 9F58D58C 9F58D754，反向 0 个 ← 两向数量不一致，链不完整）
    槽位 11：9F 58 D7 54 9F 58 D5 00 00 C0 00 00
    槽位 49：00 00 00 00 9F 58 D5 8C 00 80 00 00
  取首 peek 的现值（模型）：0

  → 结论：+8 是**载荷**，但这份固件在能被跑到的范围里从没给它写过非 0 值。
     取首恒返回 0；想让它有值，得先跑到填载荷的那段（显示初始化 + 描述符表那一路）。

H 结论
==============================================================================
能报：
  * 对象表 = 4 字节表头 [条数|项宽] + 16 字节记录 [对象|编号|0|初始计数|上限]；
    sem 表 40 条（0x54F30 起）与 flag 表 17 条（0x551B4 起）首尾相接，
    中间那一格 0x551AC 是 sem 40 的参数、0x551B0 是 flag 表头。
  * 对象 +0xC = 自己的记录地址（40/40 双向全对）——V33 的「背指表项 +4」不对。
  * 上限只在记录里，对象里没有：983 次动态访问里 +0xA 一次都没碰。
  * 上限检查代码在 0x418E8-0x418F0，但 boot 到空闲 + 空转 60 万步里没执行过。
  * 槽位 +8 = 载荷（取首唯一读出的东西）；唯一写者是 0x40384 的清零循环；
    挂链只改 +0/+4/+9 → 载荷在这台模拟里恒 0。
  * 0x9F58DA81..84 = 四字节游标（82 当前槽位 / 83 计数上限 70 / 84 下一个），
    配套 0x1BC020 的 16 字节描述符表；重挂用 82 算槽位。
  * 清空 0x12E602 的唯一（真实边界）调用点是 0x12E01E，在显示初始化 0x12E006 里。
不能报：
  * 载荷装的是什么业务值（界面元素 id？）—— 没跑到的代码不猜。
  * 描述符表 0x1BC020 每 16 字节的字段含义。
  * 0x9F58DA81 那个字节的职责（只在 5 个点被连带取用）。
  * 「显示队列在真机上跑起来了」—— 这台模拟里它一次都没转过。
