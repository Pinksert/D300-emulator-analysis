                  node->next = head->next
                  head->next = node
                  旧首节点->prev = node

D 更正 V31 / V32
==============================================================================
  V31 说：「node->next = old_head; head = node」+「+4 也存了一个节点地址」
      → 实际是**循环双链表**：+0 = next、+4 = prev（空表时 prev 就是哨兵）

  V32 说：「0x124F46 是摘 head（只有三条指令，像空桩）」
      → 实际是**初始化空表**（哨兵自指）。摘节点的代码还没找到，仍是 OPEN

  方法论：两个原语都用 `ldi:32 r12,#addr` + `call @r12` 调用。
      只扫 rel12 相对调用会得到「0 个调用点」——V31 的 exp_bqueue 就是这么写的：
      0x00124F46：rel12 相对调用 0 处 / 32 位立即数 44 处
      0x00124F5A：rel12 相对调用 0 处 / 32 位立即数 88 处
      → 正确判法是扫立即数（每个 `ldi:32` 之后就是 `call @r12`）。
      0x120458（V29 那段）用同样方法扫：立即数 0 处 → 「静态无入口」的结论仍成立。

F 结论
==============================================================================
能报：
  * 信号量表 @0x54F2C 共 40 项（16 字节/项），表尾 0x551AC，紧接 flag 表 0x551B0
  * 表项：+0 两半字 / +4 对象指针（0x68000638+(id-1)*0x10）/ +8 id<<16 / +C 0
  * 对象：+0 自指 / +4 自指（空等待队列）/ +8 计数（半字）/ +C 背指表项+4
  * 计数由 0x40910 初始化成 1；wai_sem 0x4193A、sig_sem 0x418F0 改它
  * boot 后 37 个 = 1、3 个 = 0（sem 14 / 27 / 29）；sem 17 = 1 → 二值互斥量
  * 0x124F46 = 初始化空表（哨兵自指）；0x124F5A = 插到哨兵之后（循环双链表）
  * 节点 +0 = next、+4 = prev（更正 V31 的「另一个节点地址」）
  * 槽位 +9 的唯一写入者是生产端 0x12E740（置 0x80，11 号槽位置 0xC0）
不能报：
  * 表项 +0 的语义（多数 0x00010001，但 id 1/15/28/30 是别的值）
  * 为什么 sem 14 / 27 / 29 的计数是 0（被谁占用？还是没初始化？）
  * 摘节点（消费端）的代码在哪 —— 0x12E602 在本场景没执行过
  * 「显示队列在工作」——哨兵从来没被 init，链表只是勉强成形
  * 有没有像素（仍然一条帧数据都没有）
