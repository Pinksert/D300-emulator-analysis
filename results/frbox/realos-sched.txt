2. 优先级编码器：写什么、读什么、读完怎么用
==================================================================
  调度器 0x0FE830 那几条：
    0x0FE836  ld @r12, r13        ; r13 = 就绪位图
    0x0FE838  ldi:20 #0x3F4, r14
    0x0FE83C  st r13, @(r14,0)    ; W 0x003F4 ← 位图
    0x0FE83E  ld @(r14,8), r13    ; R 0x003FC → 结果
    0x0FE842  lsl #3, r13         ; × 8 = 队列节点大小
    0x0FE844  ld @(r12,r13), r13  ; 取该优先级的队首 TCB

  实测（把位图直接写进去读回）：
    写 0x50800000 → 读回 1  （前导零 = 1）
    写 0x80000000 → 读回 0  （前导零 = 0）
    写 0x00000001 → 读回 31 （前导零 = 31）
    写 0x00008000 → 读回 16 （前导零 = 16）
    写 0x00000000 → 读回 32 （前导零 = 32）

3. ILM 的优先级约定：号越小越优先，受理条件 level < ILM
==================================================================

  这里刻意只开 xfer、不开 0x44：不开调度建模时任务 1 会一直待在
  应用区，应用/内核两侧的 ILM 才分得开。
    ILM=0x1E  内核     97600 步
    ILM=0x1F  应用     87612 步
    ILM=0x1F  内核     13541 步
    ILM=0x1E  应用      1230 步
    ILM=0x10  内核        17 步

  vec 0x3F 的 ICR 级别 = 0x1E（调度器）
  串口 vec 0x1B 的 ICR 级别 = 0x1A
  → 调度器是启用向量里级别号最大的（优先级最低），好让外设 ISR 抢占它
  → 内核 stilm #0x1E 恰好只挡调度器这一级，派发因此推迟到 reti 之后
