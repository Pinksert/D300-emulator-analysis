做出 UI 画面：实测到哪一步了

D300 固件 B 段（B3000111.bin）· NikonEmulator 实跑 · 2026-10-16
先说结论。这一轮的目标是让模拟器把 D300 的界面画出来。结果是没有画出来——而且这次能拿出硬数据说明"为什么画不出来"。 固件完整跑完 6000 万步，内存里只改动了 27 个 4KB 块、合计约 108 KB，没有任何一块是"每帧整屏刷新"级别的写入。 但同一轮里挖到了另一半东西：D300 界面上会出现的每一句话，都以明文躺在固件里，包括四级菜单的完整结构。下面两部分分开讲。

一、实测：固件运行时到底写了什么

上一轮的结论是"固件能被定时器唤醒、稳定跑在任务循环里"。这一轮要回答一个更具体的问题： 它有没有在画屏幕？判据很直白——画屏幕必然意味着往某块连续内存里整屏整屏地写。

做法是每 200 万步对所有已映射内存做一次 4KB 粒度的校验和快照，比对出"哪块被改写了"。

27运行中被改写的 4KB 块
108 KB这些块加起来的大小
0帧缓冲级别的连续写入
810全程系统调用次数
地址（4KB 块）被改写次数是什么
0x5C00300029我们手工打桩的自由运行计数器所在的块
0x6800000029EXPEED 侧某个数据表（指针表 + 定长记录）
0x9F58D00029SDRAM 里的活动结构体
0x9F5A300029SDRAM 里的活动结构体
0x9F81000018SDRAM 高段（稀疏）
0x000080007片上 RAM（内核任务控制块）
其余 21 块1–7内核数据结构、外设寄存器零星改动

注：6000 万步覆盖了"启动 304 万步 → 进空闲任务 → 手动激活定时器 → 之后约 5700 万步的任务循环"。数字取两次独立运行的一致结果。

屏幕是 640×480。哪怕只是单色 1bpp，一屏也要 38 KB；8bpp 一屏 300 KB。 改写得最凶的那几块都是 4 KB 上下的小结构体，没有一块像屏幕。

固件在等什么？——不是等硬件，是没事干

模拟器日志里那 28 个"未建模外设地址"，逐个看过去是这样的：

地址读写性质
0x00000038 / 0x39 / 0x3A0 / 6 / 104 / 8 / 10FR 低地址直接寻址区，一次性初始化
0x00000600 – 0x000006940各 1IO 端口，写一次就不再碰
0x000003E0 / 0x3E3 / 0x3E7 / 0x481 / 0x4820各 1同上

关键在于"读"几乎全是 0。如果固件在轮询某个硬件等它就绪，那个地址会被反复读。事实是它写完就再也不看了。 所以固件不是在等硬件——它启动完成后进入了正常的待机任务循环，在等外部事件（按键、镜头、存储卡）。 这也解释得通：真机开机后本来就是这样，安静地待着等用户按按钮。

试过的那个卡点：EXPEED 就绪位

上一轮注意到固件在 0x19EF40 有一段重试 8 次的循环，当时理解为"轮询 0x7000000A 的 bit4"。这一轮把它逐条拆开， 发现读法要修正——FR 的位操作指令里，立即数是"掩码"不是"位号"：

0019EF40   ldi:32 #0x70000000, r10   ; EXPEED 寄存器基址
0019EF48   ldi:8   #0x1, r9         ; r9 = 成功标志
0019EF4A   ldi:8   #0x8, r8         ; 重试 8 次
0019EF4E   add    #0xA, r0          ; r0 = 0x7000000A
0019EF50   bandl #0xD, @r0         ; 清掩码 0xD 指定的位 → 清 bit0 / bit2 / bit3
0019EF58   borl  #0x2, @r0         ; 置 bit1
0019EF5E   btstl #0x4, @r0         ; 测掩码 0x4 → 其实是测 bit2，不是 bit4
0019EF60   beq    *2               ; 没就绪就再来一轮

按"掩码"读，btstl #0x4 测的是 bit2。仿真器里 0x7000xxxx 整段没有建模、读回来恒为 0， 所以 8 次重试全失败。于是做了一个对照实验：每条指令之后把这一字节的 bit2 强行置 1，模拟"硬件过一会儿就绪"。

运行模式系统调用总数最终 PC改写块数
基线（不打桩）8100x407DC27
打桩 bit2（56,958,506 次）8100x407DC27

两项完全一致。补这一个位没有让固件多走一步。原因也清楚：这段代码在启动阶段就跑过了， 它只是"开机时确认 EXPEED 在线"的一次性检查；即便把它判通过，固件后面要做的事仍然全在 EXPEED 里，而那边一片空白。

真正的墙：D300 的显示不在 B 段手里

把这一轮的实测和之前的结论拼起来，D300 的画面通路是这样的：

B 段（富士通 FR 主控） 负责跑 μITRON、管任务、准备界面内容 → 通过 0x7000xxxx 一带的寄存器窗口跟 EXPEED 图像处理器通信 → 由 EXPEED 驱动 LCD 并把界面渲染出来。

固件里确实有 640×480 这个屏幕规格、有每个界面元素的文字，但没有帧缓冲、也没有点阵字库—— 这两样都不在 B 段的职责里。所以"让 B 段固件自己往内存里画一屏"这件事，从架构上就不会发生。

这就是为什么补外设补不出画面：要让屏幕上出现东西，得先把 EXPEED 那半边芯片也模拟出来。 NikonEmulator 里有 Expeed*IoListener 一堆占位注册，但 EXPEED 内部是空的。

二、正向成果：界面上的每一句话都在固件里

这一轮真正的收获在这里。既然画面画不出来，那就换个方向——D300 界面上会出现什么文字，固件里全都写着。

菜单文本池（0x3A7F80）

在地址 0x3A7F80 找到一张 16 项的 32 位指针表，指向 0x3AB876 起的一组界面标签 （版权信息页与闪光灯模式：Done / Artist / Copyright / Attach copyright information / TTL / Manual / Repeating flash / Commander mode）。 紧挨着指针表后面，0x3A7FC0 起是一长串没有分隔符、按菜单顺序拼接的界面文字。 把这串文字按大小写边界切开，得到 89 段，正好是 D300 的四级菜单：

帮助正文池（0x3AB91D）——连每一条说明都写着

菜单项名后面还跟着一整套帮助说明原文。从 0x3AB91D 起 18,147 字节， 用控制字节分段：0x01 是菜单项名，0x02–0x09 是各菜单的帮助正文起始， 正文内部用 0x0A 换行（共 431 个换行符）。按这个方法切出来 106 条帮助正文。

[02] View a slide show of the images in the current playback folder. [05] Match white balance to the light source. White balance can be fine-tuned by adjusting the balance of B (blue) and A (amber) or M (magenta) and G (green). [08] ISO sensitivity: Choose ISO sensitivity. Choosing higher values allows faster shutter speeds to be used to achieve optimal exposure with a given subject at a given aperture, making higher values suited to taking pictures of moving subjects or shooting under low light. [03] Auto: The camera automatically adjusts for color temperatures in the range 3500-8000 K.

里面还有两处细节值得记一笔：

  • 0x18 / 0x19 是"按键图标"占位符。原文写的是 Press [0x18] to display "Print select"——运行时会把这一个字节换成对应按钮的图形。 这和界面里"按某个键"的提示完全对应。
  • 说明文字是排版过的。换行位置都卡在固定宽度上（约 40 字符），说明固件存的是"排好版的多行文本"， 不是一整句让渲染器自己折行。

三、下一步的三条路

① 顺着 EXPEED 接口往下挖（最贴近"跑出画面"）
固件通过 0x7000xxxx 跟 EXPEED 说话。把这段窗口上的读写全部记录下来， 就有机会反推出"B 段发给 EXPEED 的显示命令长什么样"。命令格式一旦解开， 即便 EXPEED 内部不模拟，也能自己把命令解码成图像。
代价：需要先让固件真的开始发显示命令，而它现在还在待机。
② 把待机循环变成"有输入"（最可能让它动起来）
固件现在的状态是等按键。给它注入按键事件——让机身 IO 端口返回"某个按钮被按下"—— 是最有可能推动它往下走的一步。难点是 D300 的按键端口没有文档，得在运行时统计"哪个 IO 地址被反复读"来定位扫描点。
代价：需要先做一次"IO 读频次"统计，然后逐个端口试。
③ 把界面素材整理成资料（最快出成果）
2072 条短标签 + 89 段菜单文本 + 帮助文本池，已经足够整理出一份 「D300 固件里写着的界面全集」：四级菜单结构、每个选项的全部取值、 以及每一条帮助说明的原文。这对写专栏和做固件对照都有直接用处。
代价：基本只是整理工作。
