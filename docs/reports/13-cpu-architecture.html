Nikon D300 / D300S 处理器型号与架构分析

分析对象：A3000111.bin（D300，524,290 B）、B3000111.bin（D300，7,340,032 B）、 a810_010200.bin / b810_102_.bin（D300S 解密产物，同尺寸）
方法：固件静态反汇编取证 + 富士通官方内存映射交叉比对 · 全部结论可由 CRC-16 校验过的原始文件复现
一句话结论：两代机器用的是同一套处理器—— 两颗富士通 FR 系列 32 位 RISC（大端）微控制器， 其中协处理器 A 可定位到 MB91360 系列（512 KB 内部 Flash）； 主控 B 同为 FR 系列但型号不同，且必须带外部存储器总线。 EXPEED 是独立的图像处理 ASIC，不跑这两份固件。

一、架构是怎么定下来的

四份固件镜像里都嵌着同一条版权声明，位置固定：

D300 A  @0x07E471   Softune REALOS/FR is Realtime OS for FR Family,
D300 B  @0x00073D   based on micro-ITRON  COPYRIGHT(C) FUJITSU LIMITED 1994-1999
D300S A @0x07E471
D300S B @0x00073D

这条字符串只说明"用了富士通的 FR 家族"。真正把它钉死的是下面三条硬件级证据：

1. 中断向量表：FR 的 TBR 结构

A 固件末尾 1 KB（文件偏移 0x7FC00）是一张规整的 256 项大端地址表—— 这正是 FR 架构的 TBR（Table Base Register）向量表：256 个向量 × 4 字节 = 1 KB， 用于 EIT（异常 / 中断 / 陷阱）处理。

0007FC00  00 0f e2 50  00 0f e2 50  ...   ← 默认 handler 0x000FE250（210 项）
0007FF00  00 0f e7 76  00 08 12 9c  00 08 12 36  ...
0007FFF0  00 0f e2 50  00 0f e2 50  07 00 00 00  00 0f c0 00
                                    ↑ mode data   ↑ 复位向量

2. mode data = 0x07：FR 规范的强制值

向量表倒数第二个字是 0x07000000。富士通 FR 硬件手册规定： 模式数据必须放在 0x000FFFF8，且 bit31–24 必须为 00000111（即 0x07）， 否则芯片不保证正常工作。固件里这个字节精确等于 0x07。

3. 复位向量与启动代码自洽

末 4 字节 = 0x000FC000。把它当文件偏移（减去 ROM 基址 0x00080000）跳过去， 落地处正是合法的 FR 指令流：

0007C000  9f 8f 00 04 61 6c   87 10
          9f 80 00 0f fc 00   b3 00     ← 装载 0x000FFC00 并写入 TBR
          9f 8d 00 0f 80 10   97 1d
          9f 8d 00 08 00 44   97 1d

9F 8n + imm32 是 FR 的 LDI:32（装载 32 位立即数，6 字节指令）。 这段启动代码依次做了：设栈指针 → 把 0x000FFC00 写入 TBR → 初始化数据区。 TBR 值与向量表在文件中的位置完全对得上，形成闭环。

字节序（endianness）由此确认为大端（big-endian）： 向量表地址、mode data 的高位字节在前，且与富士通文档"FR family uses the big endian"一致。

二、协处理器 A：可定位到 MB91360 系列

把 A 固件的地址空间和富士通官方内存映射对照，五个区域逐一吻合：

区域A 固件实测地址MB91360 系列官方映射
内部 Flash（用户代码）0x00080000 – 0x000EFFFFFlash ROM User Code 0x080000–0x0EFFFF
引导扇区 / 向量 / 常量0x000F4000 – 0x000FFFFFSTART, CONST, VECTORS 0x0F4000–0x0FFFFF
中断向量表（TBR）0x000FFC00同上区间内
mode data / 复位向量0x000FFFF8 / 0x000FFFFCFR 规范固定位置
D-bus User RAM用到 0x0003FBB0User RAM 16 KB (D-bus) 0x03C000–0x03FFFC
F-bus Fast RAM0x00040000 起，SP = 0x0004616CFast RAM 16 KB (F-bus) 0x040000–0x043FFC

其中 D-bus / F-bus 分离是关键指纹——这是 FR 中的 Harvard 架构特征：指令总线（F-bus）与数据总线（D-bus）独立，可并行取指与取数。 MB91360G 系列的片上资源正是这样组织的：

MB91360G 系列 I/O Map（官方）
  0x000000 – 0x000400   直接寻址 I/O 区
  0x010000 – 0x010FFC   I-Cache      4 KB
  0x011000 – 0x011FFC   I-RAM        4 KB
  0x03C000 – 0x03FFFC   User RAM    16 KB (D-bus)
  0x040000 – 0x043FFC   Fast RAM    16 KB (F-bus)
  0x050000 – 0x0507FC   Boot ROM     2 KB
  0x080000 – 0x0FFFFF   Flash ROM  512 KB
判定：A 处理器属于富士通 MB91360 系列（512 KB Flash 版本）。 该系列公开型号中 512 KB Flash 的有： MB91F362GAMB91F365GBMB91F366GB MB91F367GBMB91F368GBMB91F369GA （最高 64 MHz，36 KB RAM，5 通道 DMA，16 通道 10-bit A/D，CAN / I²C / UART / 步进电机控制器）。
无法唯一确定的部分：固件里没有任何芯片型号字符串 （已扫描 MB9/MB90/MB91/FR60/FR70/FR80 等关键字，零命中）。 尼康对这类定制 MCU 通常打自己的丝印料号。此外实测的 Fast RAM 用到 0x0004616C， 略大于文档标称的 16 KB，说明可能是更大 RAM 的版本或尼康定制规格。 因此只能定位到系列，不能落到具体型号后缀。

A 的中断资源使用情况

256 个向量中，210 个指向同一个默认 handler 0x000FE250（未使用）， 46 个挂了专属服务程序，共 45 个不同的入口。 有实际中断源的向量段集中在 191–248，对应定时器、UART、A/D、外部中断等片上外设。 这与"协处理器负责测光、对焦驱动、按键扫描"的角色吻合。

三、主控 B：同为 FR 系列，但不是同一颗芯片

B 固件 7 MB，头部就是启动代码。用同样的 LDI:32 解码：

00000000  9f 80 50 00 00 00   c0 11  15 01  87 10
          9f 8f 00 00 84 00            ← 栈指针 = 0x00008400
          9f 80 00 0e fc 00   b3 00    ← TBR  = 0x000EFC00
          9b 00 06 00  9b 41 01 75  ...  ← 逐个填充向量表

启动模板与 A 完全同构（设栈 → 写 TBR → 填向量）， 证明指令集与 A 相同；但地址常量完全不同，证明是另一颗芯片：

特征协处理器 A主控 B
TBR 向量表0x000FFC000x000EFC00
初始栈指针0x0004616C0x00008400
片上 RAM 基址0x00040000（F-bus）0x00008000
片上数据区0x0003C000 / 0x00040000 双总线0x00008400 – 0x000084BC 一带
高端地址常量无0x68000000 一带（外部空间）
固件规模512 KB（内部 Flash 装得下）7 MB（必须外扩）
镜像内含向量表有无（全片扫描未找到）

三条推论

  1. B 必然带外部存储器总线。7,340,032 字节的映像远超任何 FR 单片机的内部 Flash 容量 （该系列上限 512 KB）。代码只能放在外部 Flash 上执行（XIP）。
  2. B 的引导由内部 Boot ROM 完成。7 MB 镜像里找不到任何 256 项向量表 （放宽到"≥120 项同值"扫描仍无命中），说明镜像只是应用程序映像， 向量表在芯片内部 ROM 或运行时构造。
  3. B 的性能档位更高。它承载了菜单、文件系统、TCP/IP + FTP 栈、 15 国语言包、ICC 色彩配置和 FotoNation 红眼算法库，是整机的事务中心。
佐证 A/B 同架构：B 固件偏移 0x700 处（REALOS 版权串紧前面） 的 RTOS 初始化代码，与 A 固件偏移 0x7E430 处字节级同构—— 同一段 d0 6e / d0 b1 / ... 指令序列 + 同一条 9f 80 <addr> / 9f 81 00 00 00 01 / 14 01 调用模板， 只是地址常量不同（A 用 0x0003FBB0，B 用 0x6800B984）。 这是两家共用同一套 REALOS/FR 启动流程的直接证据。

四、D300 与 D300S：硬件平台完全相同

这是本次分析最干净的一条结论，有两处字节级证据：

比对项结果
A 固件中断向量表（256 项）256 / 256 完全相同，复位向量同为 0x000FC000
B 固件启动代码（前 64 字节）逐字节完全一致（含 SP=0x8400、TBR=0x000EFC00）
REALOS 版权串偏移两代完全相同（A: 0x7E471，B: 0x73D）
固件内容差异A 约 86%、B 约 73% 的字节不同（此前比对结果）
结论：D300S 沿用了 D300 的整套处理器方案——同样的芯片、同样的内存映射、同样的链接布局， 软件则大幅重写（新增视频拍摄、双卡槽、外接麦、HDMI 等）。 这正是"向量表一模一样、但固件内容七成不同"所表达的含义：硬件不动，代码推倒重来。

一处有趣的差异

两代 B 固件的片上数据区常量不同：D300 集中在 0x000084xx， D300S 集中在 0x000090xx。这不是硬件变了（启动代码字节级相同）， 而是链接器给全局变量分配的地址随版本挪动，属于纯软件差异。

五、关于 EXPEED

A、B 两份固件中都没有出现 EXPEED 字样。 结合公开拆解资料（EXPEED 是独立封装、丝印尼康自家料号的图像处理 ASIC），可以确认：

  • EXPEED 不跑这两份固件。它是专用的图像流水线和降噪 ASIC， 负责去马赛克、白平衡、压缩等重算力工作，与运行 REALOS/FR 的 MCU 是两套东西。
  • 整机至少有三颗处理器：EXPEED 图像 ASIC + 主控 MCU（B 固件） + 协处理器 MCU（A 固件），再加上 Multi-CAM 3500DX 对焦模块和 1,005 像素 RGB 测光传感器里的专用电路。
  • 固件里能看到的第三方代码签名是：富士通 REALOS/FR（RTOS）、 NEC CIPHERUNICORN-S（加密库，在 A）、FotoNation RedEye Library v2.10.0.0（红眼修正，在 B）。
