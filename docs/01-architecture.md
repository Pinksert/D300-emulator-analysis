# 解出来的静态结构

全部是 **CPU 地址**。读固件文件时减 `0x40000`。

---

## 1. 平台

| 项 | 值 |
|---|---|
| 架构 | 富士通 FR（FR30/FR80 系），32 位 RISC，大端，**16 位定长指令** |
| 工具链 | FUJITSU + ITRON + Softune（Softune REALOS/FR 版权串在 `0x0004073E` 有明文） |
| OS | μITRON / REALOS |
| B 段基址 | `0x00040000`，长度 **7 MB** |
| A 段（协处理器） | 另一颗芯片，**不是 FR**，未模拟 |

FR 指令集的两个反直觉之处：

- **位操作立即数是掩码。** `BANDL #0xD` 实为 `byte &= (0xF0 | 0xD)`，**只清 bit1**；`BTSTL #0x4` 测 **bit2**
- **延迟分支。** 分支指令后的那条指令无论如何都会执行

## 2. μITRON 内核

```
dispatch          0x00040668
空闲任务          0x000407DC
中断向量表 TBR    0x000EFC00
向量 n 的槽位      TBR + (255 - n) * 4      ← 倒序！
系统调用陷阱      INT #0x40  →  向量 191
服务号            R12 的低 8 位（负数，n ∈ [-176, -1]，正数要过滤掉）
心跳计数器        0x5C003034
```

### 服务号与参数顺序

| 服务 | 号 | flag 号 | 位模式 / waiptn | 其他 |
|---|---|---|---|---|
| `wai_flg` / `twai_flg` | −46 | **R5** | R6 | R7 = wfmode，R4 = p_flgptn |
| `set_flg` | −48 | **R4** | R5 | |
| `clr_flg` | −47 | **R4** | R5 | |

> ⚠️ **两套顺序不同。** 按 `set_flg` 的顺序读 `wai_flg`，读出来的"flag 号"是一串内存地址。

`wfmode` 判定位 = `R7 & 0x02`：置位 = OR 等待（任一位命中即返回），清零 = AND 等待（全部命中）。R7 必须 ≤ 3。

### 任务表 `0x00054C10`

28 条 × `0x1C`。已知的几条：

| # | 入口 | 角色 |
|---|---|---|
| 1 | `0x1200AC` | 开机总装配 |
| 4 | **`0x12DFAE`** | **显示状态更新（真正的显示任务）** |
| 6 | `0x175192` | 按键处理 |
| 19 | `0x198062` | （一度被误认成主显示任务） |
| 21 | `0x242DA0` | 等 flag 10 —— 显示的下游 |

### flag 对象表 `0x000551B0`

17 条 × 16 B，表头是 `u16 条目数 + u16 元素大小`。

```
flag N 的控制块 = 0x680008B8 + (N-1) * 0x10
    +0    等待队列链
    +8    ★ 位模式（flag 3 → 0x680008E0）
    +0x0E wfmode（半字）
    +0x14 waiptn
```

## 3. 显示管线

**任务 4，入口 `0x12DFAE`**：

```
0x12DFAE  主循环
  → 0x12E006  重置
  → 0x12E0F8  从链表取下一个待绘制 id
  → 0x12E162  ★ 等 flag 3（twai_flg(3, waiptn=0x74, OR, tmout=100)）
  → 0x12E1EC  选对象，填 0x9F58DA82（当前 id）/ 0x9F58D858（= 0x1BC020 + id*16）
  → 0x12E326  取数据（★ 内部又等一次 flag 3）
  → 0x12E412  拷数据
  → 0x12E674  ★ 绘制（调用描述符 +0x0C 处的函数指针）
```

失败分支回 `0x12E48E`。

### 显示对象描述符表 `0x001BC020`

70 条（id `0x00`–`0x45`）× 16 B：

```
+0   u32  数据缓冲指针
+4   u32  长度
+8   u32  类型（0 / 1 / 2）
+0C  u32  ★ 绘制函数指针
```

### 函数指针表 `0x001BC480`

紧跟在描述符表屁股后面，**25 项**，全部落在 `0x12F778`–`0x12FD9E`。表尾 `0x1BC4E4` 是 `00020103`，后面接 printf 的 `"%3d "` 格式串。

这 25 项里，`0x12F77A` / `0x12F952` / `0x12FAEA` / `0x12FD9E` 会执行 `set_flg(3, 0x10)` —— 正是显示管线死等的那个 bit4。

### 待绘制链表

```
链表头      0x9F58D500
节点数组    0x9F58D508 起，12 B/个
    +0  next
    +4  prev
    +8  id（最高位 0x80 = 待更新/脏）
当前 id     0x9F58DA82
描述符指针  0x9F58D858  = 0x1BC020 + id * 16
源缓冲      0x9F58D87C
目标缓冲    0x9F58D97C
```

### 两个中断源按状态字节索引分发表

| 请求号 | 向量槽 | ISR | 分发表 | 状态字节 |
|---|---|---|---|---|
| `0x1B`（Serial IF 0 共享） | `0x000EFF90` | `0x12FDB4`（RETI 结尾） | `0x1BC490`（21 项） | `0x9F58DA86` |
| `0x20`（EXT9） | `0x000EFF7C` | `0x12FE54`（RETI 结尾） | `0x1BC480`（4 项） | `0x9F58DA85` |

ISR `0x12FDB4` 操作的是 `0x7000000A` —— EXPEED 串行口的时钟/数据脚。**显示管线要的那个 bit4，是从串行口中断里来的。**

### "绘制"实际做了什么

- `0x12F452`：全文只有 `set_flg(0x0A, 0x8000); RET`
- `0x12E8E2` / `0x12E806`：拿数据缓冲与状态字节逐位比对，变了才更新并置标志

**B 段不画像素，它只维护状态并通知下游。** 等 flag 10 的 `wai_flg` 在 `0x242BF4` / `0x254FFE` / `0x25D3CA`，属任务 21 范围。

## 4. B ↔ EXPEED 总线

**位串行，不是显存。**

```
CS    0x70000002  bit2
CLK   0x7000000A  bit1
DATA  0x7000000A  bit2
```

- 8 位，**LSB 先**
- 命令字节 = `寄存器号 | 读标志 0x80`
- BCD ↔ 二进制转换用两张 256 B 表：
  - 编码（CPU→EXPEED）`0x001CFCA8`
  - 解码（EXPEED→CPU）`0x001CFDA8`
- 开机初始化 **20 字节**
- 心跳命令 **0xA6**，读 7 字节，跑了 32 次
- 应答 `0x86` 的 bit7 触发分支

### 心跳 0xA6 的字段映射

用一组标记字节做实验钉死的：

```
buf = [b1, b2−1, b3−1, b5, b6, b7]
      年  月    日    时  分  秒
```

**第 4 个字节被丢弃。** 全 BCD，月和日进内存时各减 1。

## 5. 串行口直接页寄存器

跑 `D300Isr` 时实测到的值：

```
0x60 = 02      0x61 = 31（发送字节）   0x62 = 03    0x63 = 18
0x64 = 未映射   0x65 = 10               0x66 = 00    0x67 = 01
0x38 写 0xFB 清中断
```

## 6. 界面文字资源（静态提取用）

```
短标签区        0x001C0000   2072 条
菜单池指针表    0x003A7F80   89 段
帮助正文        0x003AB91D   106 段
```

UI 编码：ASCII 1 B + CJK 2 B 转义；分隔符 D300/D3 = `0F07`、D300S = `0F08`、D90/D700 = `0F09`；末 2 B = CRC16/XMODEM。

## 7. 按键链路

```
IRQ 通道 3 → 请求 0x13 → 向量 0x42A2C
  → ISR 0x17584C       set_flg(12, 0x80000000)
  → 消抖 0x175876      读 0x50000107 bit3，tslp_tsk(10)
  → 任务 6 (0x175192)
  → 显示更新 0x198004   sta_tsk(20) / set_flg(14, 0x40000000)
  → 任务 19 (0x198062)
```

注入按键的实测：剂量严格线性（按 1/3/10/30 次 → 接受 1/3/10/30 次）。但**任务 6 在基线里根本没被拉起**（`0x1200AC` 调用了 `0x175186` 却从未进入），所以按键实验的结论可信度要打折。
