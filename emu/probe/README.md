# probe/ —— 取证脚本

这些不是模拟器的一部分，是**用来逼出结论的一次性实验**。每个脚本都对应报告里的一张表，
保留它们是为了让结论能被别人重跑，而不是只能相信文字。

统一约定：

- 都能在仓库里直接跑：`cd emu && python probe/exp_482.py`；
- 固件路径走 `FRBOX_FW_DIR` 或仓库 `data/`，没有一个脚本写死绝对路径；
- 输出打到 stdout（需要留档就 `> ../results/xx.txt`），不写别的文件；
- 判据写在 docstring 里，"什么算验证通过"必须先说清再跑。

### V46：`0x40` 窗口（寄存器面 + 曲线表下载口）+ `0x60/0x61` 双通道控制器

| 脚本 | 做什么 | 出处在 |
|---|---|---|
| `exp_dual40.py` | A–H 八段：建器件前后总账（写 1,853→**112**、读 5 地址/9 次→**0/0**）/ `0x60`+`0x61` 的 16 笔逐条访问 + 两段反汇编（`0x1A36BC` 初始化、`0x1A36DA` 查状态）+ `0x8400`/`0x8450` 两张 0x50 字节描述符表 / **256 个状态值逐个直接调 `0x1A36DA`**（64 个命中 ⇒ 字段在 bit2–3、== 3 就绪）/ `0x40` 按写 PC 归组（54 PC / 1,650 笔 → 寄存器实例 + `+0xF8` + 下载口）/ `+0xF8` 两次 RMW 的三个实例终值（`0x3B3B` / `0x1D1D` / `0x0000`）/ 6 张表逐字节与 ROM 比对 **6/6 全等**（1,541 项 = 3,082 字节）/ 反事实三档（`0x00` / `0x0C` / `0xFF`：覆盖 5,404→**5,421**、其余全不变）/ 剩余 112 笔的分布 | V46 全篇（`dual40.txt`） |

⚠️ **`lsl2` / `lsr2` 的位移是 u4 + 16**（KI#181）：`#12`/`#14` 是 28/30 位，
合起来取的是 **bit2–3**，不是 bit1。判字段位置别靠「移位对消」推 ——
把 **256 个值逐个喂进去看哪些命中**（64 个命中，全部落在 bit2–3 == 3）。
这个坑的代价是：掩码写错 → 反事实「怎么改都不变」→ 差点得出「这位没用」的假结论。
⚠️ **判「是不是整块拷贝」要按源地址不连续切段**：只比首地址会把「6 张不同曲线表」
读成「一张表」（`0x40` 的下载口就是这种，KI#179-b）。切段判据：
`rec[k][2] != rec[k-1][2] + 2`。
⚠️ **阴性结果也要写清**：`0x60` 的状态字段置成「就绪」只让覆盖 +17 个指令字，
换手 / 入口 / 末 PC 一个都不变 —— 因为 8 个调用点都紧跟 `ldi:8 r4, 0`
把返回值清掉了。不写清的话，下一版还会有人去查「这个状态位到底影响什么」。
⚠️ **一块窗口里可能同时有「寄存器」和「数据汇」**：`0x40` 的 1,650 笔写里，
51 个写点是寄存器实例（可回读、有 RMW），1 个写点是 1,541 笔的批量下载口。
「按地址段一刀切定性」会两头都错（V44 就把它整体叫「只写数据汇」）。
